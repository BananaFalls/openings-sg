## What was done, in order

1. **Scraper verified against the live MCF API.** Endpoints, all 43 category names and field paths were correct. Fixed a crash on Windows when writing non-Latin characters, made writes atomic, widened retries, and made a partial crawl exit non-zero.
2. **Stack built by three parallel agents against one shared contract:** `db/schema.sql`, the scraper's `--supabase` mode and the workflow; the FastAPI back end in `backend/`; the Next.js front end in `frontend/`.
3. **Deployed.** Git repo created and pushed, both halves on Vercel, schema installed in Supabase, secrets set on GitHub and Vercel, first full scrape run from GitHub Actions.
4. **Auto-deploy fixed.** Vercel had blocked a deploy because the commit author was not linked to the Vercel account. Both projects are now connected to the GitHub repo, so a push to `main` deploys them.
5. **Header restyled**, later simplified (see 9).
6. **Openings dropped in favour of postings.** Removed from the database views, the API and every page; the nightly vacancy lookups were removed from the schedule.
7. **Daily history started.** `history_sector` and `history_role` get one row per day after each full, clean crawl. The first day saved is 13 Oct 2026.
8. **Google Search Console** verified with a meta tag in `frontend/app/layout.tsx`; `sitemap.xml` (1,835 pages) submitted.
9. **Home page changes:** role search box, intro centred with the figure tiles below it, labour market (U-6 style) panel removed from the home and Hiring season pages, top bar flattened with no logo and the system font.

## Decisions and why

- **Postings, not openings.** MCF's search results carry no vacancy count. Fetching it per job ran at about 23 lookups a minute from GitHub's servers, so coverage reached only 3.6% and would never have caught up with roughly 2,200 new postings a day.
- **Existing Supabase project used.** The access token could only reach the project created on 8 Oct, which was empty, so the schema went there instead of a new Singapore project.
- **Pay under S$300 a month is treated as missing** in pay statistics (about 2% of postings advertise figures such as 1–1).
- **The raw MCF object is stored without the job description,** and cleared for jobs gone more than 30 days, to stay inside the 500 MB free tier.
- **History is saved only after a complete crawl,** so a half-failed night never appears as a false dip.
- **No salary structured data.** Google stopped showing its "estimated salary" result type in 2025, and role pages already carry the pay range in their description.
- **The top bar no longer sticks while scrolling,** because without a background its text would overlap page content.

## How to change things from here

- **Code:** commit and push to `main`; Vercel builds both projects.
- **Database schema:** paste the whole of `db/schema.sql` into the Supabase SQL editor and run it. It is safe to re-run. Deploy code that stops reading a column before removing that column.
- **Previewing the front end:** in `frontend/`, set `API_URL=https://openings-sg-api.vercel.app` and run `npx next dev`.
- **Tests:** `python -m pytest backend/tests` (133 tests). The scraper's offline checks were run from a scratch folder and are not in the repo.

## Open items

- **Role names are fragmented.** "Data Analyst" shows 30 postings because variants such as "HR DATA Analyst" count as separate roles. Now that search is on the home page, cleaning up `role_of()` in the scraper is the most visible data improvement.
- **Show the history on the site** (week-on-week change, new postings per day) once a few weeks exist. The Hiring season page stays thin until then.
- **Domain.** The site is on a `vercel.app` address. After buying a domain, point it at Vercel, set `NEXT_PUBLIC_SITE_URL`, and repeat the Search Console steps for the new address.
- **About page copy** was reworded by the front end agent and has not been reviewed by the founder. `SUPPORT` (kopi, PayNow, business email) is still empty.
- **MCF terms of use** have not been checked for the daily crawl.
- **Storage:** roughly five to six months on the free tier at current volume; old `jobs` rows can be removed once the history tables carry the trends.
- **GitHub Actions minutes:** a private repo gets 2,000 a month; the nightly run should use about 1,100 now the lookups are gone. The first shorter run has not happened yet, so that figure is an estimate.
- **Unused code left in place:** the scraper's `--details` flag, the `vacancies` column and `set_vacancies()`; `frontend/components/LabourPanel.tsx`, `LabourChart` and `frontend/lib/labour.ts`. Delete or reuse.
- **Not tested:** Safari and Firefox rendering, screen readers, and the nightly run with the new history and pruning steps (first one is the night of 13 Oct).
